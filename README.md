# Прокачка персонажа

Личный трекер доходов, долгов, бюджета, книг, тренировок и целей. Записи копятся в опыт, из опыта считается уровень. Команды можно надиктовать или написать по-русски: разбор происходит в браузере, без внешних моделей.

Один пользователь, без аккаунтов. Часовой пояс — Ульяновск, `Europe/Samara` (UTC+4): «сегодня», «вчера» и текущий месяц считаются по нему.

## Стек

- Cloudflare Workers и статика через binding `ASSETS`
- D1 `progress-character-db` (`DB`)
- Небольшой фронтенд на Vite, без UI-фреймворка

`src/worker.js` отвечает на `/api/*`. Остальные запросы уходят в `env.ASSETS.fetch()`. Для SPA включён `not_found_handling = "single-page-application"`, а `run_worker_first = true`, чтобы fallback на `index.html` не перехватывал API.

## Локальный запуск

Нужны Node.js 22 и зависимости из репозитория.

```bash
npm ci
npm test
npm run build
npx wrangler d1 migrations apply progress-character-db --local
npm run dev
```

Приложение откроется на `http://127.0.0.1:8787`.

Проверка API на уже запущенном локальном Worker:

```bash
node scripts/smoke.mjs
```

Демо-данные для пустой локальной базы (уровень около 12, чтобы главный экран был заполнен):

```bash
node scripts/seed-demo.mjs
```

## Деплой

Секреты репозитория: `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`. Токену нужны права на Workers и D1, не на Pages.

При пуше в `main` workflow `.github/workflows/deploy.yml` прогоняет тесты, собирает фронтенд, применяет миграции (`wrangler d1 migrations apply progress-character-db --remote`) и выполняет `wrangler deploy`.

Необязательный PIN: если задать секрет `APP_PIN`, каждый запрос к `/api/*` должен присылать заголовок `X-App-Pin`. Пустое или отсутствующее значение проверку отключает. Сравнение секрета постоянное по времени (SHA-256 и `timingSafeEqual`).

```bash
npx wrangler secret put APP_PIN
```

В интерфейсе PIN вводится в «Настройках» и хранится только в браузере.

## Данные

Всё лежит в D1, у каждой сущности есть создание, правка и удаление:

- доход: сумма, тип (активный / пассивный), описание, дата
- долг: кто, направление (я должен / мне должны), сумма, оплачено, остаток
- бюджет месяца
- цель: название, прогресс, статус
- книга: название, статус, страницы
- тренировка: тип, длительность, дата

Удаление записи снимает связанный с ней опыт.

## Опыт и уровни

| Действие | XP |
| --- | --- |
| Активный доход | 15 + 1 за каждые 10 000 ₽, не больше +50 |
| Пассивный доход | 25 + 1 за каждые 10 000 ₽, не больше +50 |
| Тренировка | 20 + 1 за каждые 10 минут, не больше +30 |
| Новая книга | 5 |
| Книга прочитана | 100 |
| Новая цель | 10 |
| Цель выполнена | 80 |

Бюджет и долги опыт не дают. Повторное сохранение той же суммы не наращивает опыт: начисление заменяется.

Переход с уровня L на следующий стоит `100 + (L − 1) × 50` XP. С 1 на 2 — 100, со 2 на 3 — 150, дальше с тем же шагом. Уровень считается из суммы всего опыта.

## Голосовые команды

Язык распознавания — `ru-RU` (Web Speech API). Если браузер его не умеет, ту же фразу можно ввести текстом и нажать Enter. Перед записью показывается разбор, поля можно исправить. Удаление не выполняется, пока его не подтвердить.

Суммы понимаются словами и сокращениями: «пятьдесят тысяч», «50к», «50 к», «50 тыс», «полтора миллиона», «1,5 млн», «двадцать пять тысяч пятьсот», «2кк».

Примеры:

- `получил 50к за маркетинг для Ивана` — активный доход 50 000 ₽, описание «Маркетинг для Ивана»
- `пассивный доход 15 тысяч аренда` — пассивный доход
- `дивиденды 3к`
- `должен Ивану 10к` — я должен
- `Петр должен мне 20 тысяч` — мне должны
- `бюджет на декабрь 80 тысяч`
- `тренировка бег 40 минут`, `пробежка полчаса`, `йога сорок пять минут`
- `книга Сапиенс 412 страниц`
- `дочитал Атомные привычки`
- `прочитал 30 страниц атомные привычки`
- `цель накопить 300 тысяч`
- `выполнил цель марафон`
- `удали последний доход`
- `удали тренировку от вчера`
- `удали книгу сапиенс`

Парсер — отдельный модуль `src/parser/parseCommand.js`. Тесты: `npm test`.
